# Demo data

Everything here is synthetic. Emails use `@example.com`, phone numbers are generated, brand names are
real but model names and prices are invented.

## Load it

```bash
make migrate
make seed                                            # same as: uv run python -m scripts.seed_database
uv run python -m scripts.seed_database --anchor-date 2026-11-04T12:00:00   # optional: pick "now"
```

The seed is **idempotent** (run it twice, nothing is duplicated) and **deterministic**.
Dates in `data/raw/*.json` are relative to the anchor in `data/raw/_meta.json`; the seed shifts all of
them so that "now" is the moment you run it. A late order stays late, a "delivered 3 days ago" order
stays 3 days old.

## What is in the database

| Table | Rows | Notes |
|---|---|---|
| categories / brands | 4 / 12 | electronics -> mobiles, laptops, audio |
| products | 45 | 15 per category, 3 inactive, 2 out of stock, some with `old_price_egp`, 1 non-returnable group (earbuds) |
| product_images | 93 | placeholder SVGs in `static/products/` |
| orders | 120 | statuses: delivered 70, cancelled 12, returned 8, shipped 7, confirmed 6, return_requested 6, pending 6, out_for_delivery 5 |
| order_items / order_status_history | 148 / 536 | history is consistent with each order's status |
| returns | 17 | 6 requested, 8 received/refunded, 3 rejected (order goes back to `delivered`) |
| reviews | 90 | only on delivered/returned items, one per item, Egyptian Arabic |
| carts / cart_items | 12 / 10 | 4 customers have items in their cart |
| policies | 4 | shipping, returns, warranty, cancellation (numbered `## n.` sections) |

Things the data is built to exercise:

- **Multi-seller checkouts:** 12 checkouts produced two orders (one per seller) with the same `checkout_group_id`.
- **Seller trends:** `seller1`, `seller2` and `seller4` sell more in the last 30 days than before, `seller3` sells much less (for the period comparison).
- **Price drift:** some old orders have a `unit_price_egp` different from the current product price.
- **Payments:** `cod` stays `pending` until delivered; `card`/`wallet` are `paid`, `refunded` when cancelled or returned.
- **Rating aggregates:** `products.rating_avg/rating_count` and `sellers.rating` are computed from `reviews` at the end of the seed.
- **Some products have a recurring complaint** (battery, heat, slow UI) so review analysis has something to find.

## Business rules the data follows

- Cancel only while `pending` or `confirmed`. After shipping there is no cancel, even if the order is late.
- Return within **14 days** of delivery (day 14 accepted, day 15 rejected), only for returnable products.
- Shipping fee 60 EGP, free from 5000 EGP. Delivery: +2 days for Cairo/Giza/Alexandria, +4 days elsewhere.

## Regenerating the files

The JSON files and SVGs are generated by `scripts/seed_generator/` and committed. Regenerate only if you
change the catalog or the texts:

```bash
cd scripts/seed_generator
uv run python generate.py --base ../../data/raw --out ../../data/raw --static ../../static/products
```

`users.json`, `addresses.json`, `sellers.json`, `brands.json` and `categories.json` are inputs (owned by
the team); the generator only reads them and writes `products`, `orders`, `returns`, `reviews`,
`carts`, `policies` and the SVGs.
